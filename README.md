# ИИ-ассистент для анализа юридических документов с использованием RAG

## Описание проекта

Данный проект представляет собой разработку ИИ-ассистента, который помогает анализировать юридические документы и находить в них важную информацию. Ассистент будет использовать технологию Retrieval-Augmented Generation (RAG), которая позволяет искать данные в базе документов и формировать ответы на основе найденной информации.

Основная задача проекта — упростить работу с юридическими текстами, сократить время на их анализ и снизить риск пропуска важных условий, противоречий или правовых рисков.

## Почему выбрана эта тема

Тема выбрана потому, что анализ юридических документов требует внимательности, занимает много времени и связан с высокой ответственностью. Даже небольшая неточность или пропуск существенного условия могут повлечь правовые и финансовые последствия.

Использование ИИ в такой задаче позволяет автоматизировать первичный анализ документов, ускорить поиск нужной информации и повысить качество работы с юридическими текстами. Кроме того, эта тема актуальна, поскольку технологии искусственного интеллекта всё активнее применяются в профессиональной деятельности, в том числе в юридической сфере. Проект позволит изучить современные подходы к обработке документов и применить их на практике.

## Блок 3.1. Function Calling

В этом блоке в ассистента добавлен механизм Function Calling. Модель может не только отвечать текстом, но и вызывать Python-функции для работы с внутренней базой документов.

В проекте реализованы два инструмента:

- `search_documents(query, department, doc_type)` — ищет документы по запросу, отделу и типу документа.
- `extract_key_fields(document_id)` — извлекает из выбранного документа ключевые поля: стороны, дату, сумму и риски.

Данные для инструментов хранятся в `data/documents.json`. Описания инструментов вынесены в `app/prompts/tools/`, а системный промпт ассистента — в `app/prompts/system_v1.j2`.

### Проверка работы

#### Сценарий 1: запрос требует вызова инструментов

**Запрос:** `Найди договор с Альфой и извлеки из него ключевые поля.`

Ассистент сначала вызвал `search_documents` и нашел документ `contract_001`, затем вызвал `extract_key_fields` для извлечения полей. В финальном ответе были указаны название договора, дата, стороны, сумма и найденные риски.

#### Сценарий 2: запрос не требует вызова инструментов

**Запрос:** `Объясни простыми словами, что такое RAG.`

Ассистент не вызывал инструменты, потому что вопрос был общим и не требовал поиска по базе документов. Ответ был сформирован обычным текстом: RAG объяснен как Retrieval-Augmented Generation, то есть подход, при котором модель сначала ищет информацию в базе, а затем генерирует ответ на ее основе.

#### Сценарий 3: пограничный запрос

**Запрос:** `Есть ли у нас документы про персональные данные?`

Ассистент решил использовать `search_documents`, потому что вопрос может относиться к внутренней базе документов. В результате был найден документ `policy_001` — "Политика обработки персональных данных".
