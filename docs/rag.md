# RAG — документация (Блок 5.3)

## Зависимости

| Пакет | Версия |
|---|---|
| llama-index | >=0.14.22 |
| llama-index-vector-stores-qdrant | >=0.8.8 (установлено 0.10.2) |
| llama-index-readers-file | >=0.6.0 |
| qdrant-client | >=1.14,<1.16 (установлено 1.15.x) |

**Важно:** верхняя граница `qdrant-client<1.16` обязательна — версия 1.19+ несовместима с `llama-index-vector-stores-qdrant 0.10.2` (ломается импорт `IDF_EMBEDDING_MODELS`).

## Решение по коллекциям

Коллекция из Б5.2 (`documents`, 1308 точек) наполнялась напрямую через `qdrant-client` с плоским payload. LlamaIndex хранит ноды в собственном формате (`_node_content`), поэтому при подключении к «чужой» коллекции метаданные и цитаты `source_nodes` были бы неполными.

Для блока 5.3 заведены две отдельные коллекции:

| Коллекция | Кто наполняет | Формат payload |
|---|---|---|
| `rag_block_03` | LlamaIndex (`VectorStoreIndex.from_documents`) | `_node_content`, `_node_type`, метаданные файла |
| `rag_block_03_bare` | bare-metal (`qdrant-client` напрямую) | плоский `{text, source}` |

**Параметры индекса:** модель `text-embedding-3-small`, dim=1536, distance=COSINE, chunk_size=512, chunk_overlap=64.

## LlamaIndex vs Bare-metal

| Критерий | LlamaIndex | Bare-metal |
|---|---|---|
| Строк кода (ingestion + query, без импортов) | ~30 | ~55 |
| Поддержка форматов из коробки | .md, .txt, .pdf, .docx, .html и др. (через `SimpleDirectoryReader`) | только то, что читаешь вручную (в нашем случае `.md`) |
| Что дописать для PDF/DOCX | ничего — `llama-index-readers-file` уже установлен | парсер PDF/DOCX вручную (pypdf, python-docx) |
| Что дописать для batch-ingestion / async | `VectorStoreIndex.from_documents` уже async-ready; `aquery` доступен | обернуть `_embed` и `upsert` в asyncio вручную |
| Где удобнее дебажить top_score / source_nodes | удобно: `response.source_nodes` содержит текст, метаданные, score | удобно: `hits` — простой список с payload и score |
| Где гибче подменять компоненты (re-ranker, chunker) | LlamaIndex: через `Settings` и pipeline API | bare-metal: полный контроль, но всё вручную |

**Вывод:** в дипломе остаётся версия на **LlamaIndex** (`app/services/rag.py`). Причины:
1. Нормальный чанкинг по предложениям (`SentenceSplitter`) — bare-metal берёт первые 4000 символов файла и попадает в служебный заголовок КонсультантПлюс, что снижает качество retrieval (score 0.527 vs 0.656 на одном вопросе).
2. Поддержка форматов из коробки — не нужно писать парсеры отдельно.
3. Async query engine (`aquery`) совместим с FastAPI без дополнительных обёрток.

## Прогон 5 вопросов

### 1. «Каков размер неустойки за просрочку арендной платы?» — хороший

| | |
|---|---|
| **Ответ** | 0,1 процента от суммы долга, включающей НДС, за каждый день просрочки |
| **top_score** | 0.637 |
| **top-1 source** | Договор аренды нежилого помещения.md |
| **Оценка** | Релевантно |
| **Гипотеза** | Точная формулировка из договора совпала с запросом — retrieval попал в нужный чанк с первого раза |
