# Лекция 3.3. Асинхронная обработка запросов к ИИ

## 1. Проблема, которую решает асинхронность

Запрос к LLM — это почти целиком **ожидание сети**: Python отправил запрос и ~99% времени просто ждёт ответ. Процессор в это время простаивает.

Синхронный код обрабатывает запросы по очереди:

```
запрос 1 (5 сек) → запрос 2 (5 сек) → запрос 3 (5 сек) = 15 сек
```

Асинхронный — отправляет все сразу и ждёт всех вместе:

```
запросы 1, 2, 3 одновременно → ~5 сек
```

**Вывод:** асинхронность не ускоряет сам запрос, она убирает простой между запросами.

## 2. Базовые понятия

### Конкурентность vs параллелизм

- **Конкурентность** — несколько задач «в работе», но физически выполняется одна; переключаемся, пока другая ждёт. *Поставил чайник — пока греется, режешь хлеб.*
- **Параллелизм** — задачи реально выполняются одновременно (разные ядра/люди). *Два человека на кухне.*

Для LLM нужна **конкурентность**: задачи в основном ждут сеть, одного потока хватает на сотни запросов.

### Event loop

Диспетчер задач. Крутится в одном потоке и решает:

- какая задача готова продолжиться (ответ пришёл) — выполняем её,
- какая ждёт сеть — пусть спит, не мешает остальным.

### Корутина, await, Task

```python
async def ask_llm():          # async-функция
    ...

coro = ask_llm()              # вызов БЕЗ await → корутина (ещё ничего не выполняется)
result = await ask_llm()      # запустить и дождаться результата
task = asyncio.create_task(ask_llm())  # запустить В ФОНЕ, код идёт дальше
result = await task           # позже забрать результат
```

Три правила:

| Что пишем | Что происходит |
|---|---|
| `await coro` | дождаться результата, ничего параллельно |
| `create_task(coro)` | запустить параллельно в фоне |
| `gather(*coros)` | запустить все параллельно и дождаться всех |

Корутина умеет **ставить себя на паузу** на `await`: в этот момент event loop переключается на другие задачи.

## 3. Инструменты для параллельных запросов

### asyncio.gather — пачка запросов

```python
answers = await asyncio.gather(
    ask_llm("вопрос 1"),
    ask_llm("вопрос 2"),
    ask_llm("вопрос 3"),
)
```

Параметр `return_exceptions=True`: упавший запрос не ломает всю пачку — ошибка возвращается как элемент списка:

```python
["ответ 1", TimeoutError(...), "ответ 3"]
```

Подходит, когда **частичный результат полезен** («8 документов из 10 обработались — уже хорошо»).

### asyncio.Semaphore — ограничение одновременных запросов

Проблема: 100 запросов через gather → провайдер вернёт `429 Too Many Requests`.

```python
sem = asyncio.Semaphore(8)

async def limited_ask(prompt):
    async with sem:                    # занимаем один из 8 слотов
        return await ask_llm(prompt)   # на выходе слот освобождается
```

*Аналогия: 5 касс в магазине — покупателей 100, обслуживаются одновременно 5.*

**Как выбрать число:** `floor(RPM / 60 × 0.8)`. Лимит 600 запросов/мин → 600/60 = 10 запросов/сек → запас 20% → `Semaphore(8)`.

### asyncio.TaskGroup — «всё или ничего» (Python 3.11+)

```python
async with asyncio.TaskGroup() as tg:
    t1 = tg.create_task(translate("en"))
    t2 = tg.create_task(translate("fr"))
    t3 = tg.create_task(translate("de"))
```

Если одна задача упала — **остальные автоматически отменяются**, наружу летит `ExceptionGroup`.

**gather vs TaskGroup:**

| | gather | TaskGroup |
|---|---|---|
| Одна задача упала | остальные доходят до конца | остальные отменяются |
| Когда брать | частичный результат полезен | без всех результатов смысла нет |

### ExceptionGroup и except*

TaskGroup собирает все ошибки в одну группу. Ловятся новым синтаксисом (3.11+):

```python
except* TimeoutError as eg:   # ловит ВСЕ TimeoutError из группы
    ...
except* APIError as eg:
    ...
```

### asyncio.timeout — лимит времени на блок (3.11+)

```python
async with asyncio.timeout(10):
    doc = await load_document()
    answer = await ask_llm(doc)     # 10 секунд на ВСЁ вместе
```

Лучше старого `wait_for`: накрывает несколько `await` одним лимитом и безопасно вкладывается.

## 4. AsyncOpenAI

```python
from openai import AsyncOpenAI       # вместо OpenAI

client = AsyncOpenAI()

async def ask(prompt):
    response = await client.chat.completions.create(...)   # await обязателен
```

Из коробки: retry на 429/5xx, таймауты, streaming, function calling — всё то же, но с `await`. Можно держать sync- и async-клиенты в одном проекте.

Точка входа в скрипте:

```python
asyncio.run(main())   # создаёт event loop, выполняет main, закрывает loop
```

## 5. Streaming

### От LLM

`stream=True` — ответ приходит не целиком, а кусочками (токенами):

```python
stream = await client.chat.completions.create(..., stream=True)
async for chunk in stream:
    yield chunk.choices[0].delta.content    # функция с yield = async-генератор
```

**TTFT** (time to first token) — время до первого токена. Пользователь видит начало ответа через 200–600 мс вместо ожидания полного ответа.

### До браузера: SSE

Два разных слоя, не путать:

- **LLM streaming** — OpenAI отдаёт токены частями в наш бэкенд.
- **SSE (Server-Sent Events)** — наш FastAPI передаёт эти части дальше клиенту.

```
OpenAI → (streaming) → FastAPI → (SSE) → браузер
```

## 6. Архитектурные приёмы

**Пул провайдеров.** У OpenAI и Anthropic разные лимиты → каждому провайдеру свой клиент и **свой Semaphore**. Один общий нельзя.

**Router** — решает, к какому провайдеру пойдёт запрос: дешёвые → mini-модель, сложные → Claude, провайдер упал → fallback на другого. Сам ответ не генерирует.

**Background Tasks** — долгая задача (отчёт на 30+ сек): сервер сразу отвечает «принято, id=123», работает в фоне, клиент позже спрашивает статус. ⚠️ FastAPI BackgroundTasks годятся только для некритичного (логи, webhook): рестарт сервиса = задача потеряна.

## 7. Типичные ошибки

Все три блокируют event loop — весь сервис «замирает»:

1. **Синхронный клиент в async-функции** — `OpenAI` вместо `AsyncOpenAI`.
2. **`time.sleep()`** вместо `await asyncio.sleep()`.
3. **Тяжёлые CPU-вычисления** (парсинг огромного PDF, большие расчёты) — async для ожидания сети, не для счёта; CPU-работу выносить отдельно.

## 8. Шпаргалка

| Инструмент | Зачем |
|---|---|
| `async def` / `await` | объявить корутину / дождаться без блокировки |
| `create_task` | запустить в фоне |
| `gather(..., return_exceptions=True)` | пачка запросов, частичный результат ок |
| `Semaphore(N)` | не больше N одновременных запросов |
| `TaskGroup` | группа задач «всё или ничего» |
| `asyncio.timeout` | лимит времени на блок |
| `AsyncOpenAI` | async-клиент OpenAI |
| `stream=True` + `async for` | ответ по токенам |
| SSE | стрим от сервера к клиенту |
